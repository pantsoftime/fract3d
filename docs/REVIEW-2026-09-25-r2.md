## 0. Verdict on the resolution

The first review has been implemented faithfully and, in several places, exceeded (the 2D
renderer is resumable per *iteration*, not per band; the signature/PAR/@look/prefs table; the
sampler). Independently checked:

- `cmake --build build` — no work, no warnings. `ctest --test-dir build -j4`: **57/57 in 6.3 s**.
  `ctest --preset asan`: **57/57 in 21.5 s**.
- Renders are bit-for-bit deterministic across runs (three path-traced renders of preset 07,
  `imgdiff --exact` → max 0), so the golden-image tests are sound.
- **1.6 (`rotAxis`)**: the resolution is right and the first review was wrong. Column-major
  read of the literal gives `R = cI + s[k]× + t kkᵀ` exactly (e.g. `R[0][1] = t·kx·ky − s·kz`),
  which is Rodrigues' formula for +θ. The Sierpinski call is also in the right direction:
  `R·(0,1,0) = (1,1,1)/√3`, so world +y maps to the fractal's apex axis.
- 1.1–1.4, 1.8, 2.1–2.5, 3.1–3.4 and 4.x: present and working as described, with the gaps
  listed below (1.4 has two small leaks, §2.5; 2.3 regressed slightly, §2.12).
- The four "bugs beyond the review" in the resolution (hot-reload epoch, Fresnel, GL-after-context,
  inverted clamp) are real and correctly fixed.

The remaining issues are second-order and concentrated in the newest code (camera paths/video,
deep zoom, formulas), which has had the least time to settle. Nothing structural.

## 1. Bugs confirmed by experiment

### 1.1 [P2] Video export shows the high-res render dialog; its Cancel silently kills the export
- `src/ui.cpp:231`: `if (ui.showPoster || poster.active) drawPosterDialog();` — every video
  frame runs through `poster`, so during an export a second window "Render high-res image /
  Rendering 1920x1080, 32 samples..." appears behind the Camera-path window, with its own Cancel
  (`src/ui.cpp:1460`). That Cancel sets `poster.active = false` without touching `video`, so
  `updatePoster` stops being called, `nextVideoFrame` never runs, and the export hangs at the
  current frame with ffmpeg waiting on the pipe. The path window still shows "Cancel export",
  which does work.
- Confirmed: `fract3d --path tests/menger-twist.f3dpath --render /tmp/x.mp4 --ui-shot ui.png
  --frames 4 --size 640x360 --samples 1 --fps 5` — the screenshot shows both windows.
- **Fix:** `poster.active && !poster.toVideo` for the dialog, or make that Cancel call
  `cancelVideo()` when `poster.toVideo`.

### 1.2 [P2] A camera path from a deep keyframe to a shallow one ends at the wrong center
- `loadParText` (`src/params_io.cpp:237-246`) sets `view.hpRe/hpIm` when the PAR has
  `classic.centerHP` and otherwise leaves the previous strings in place (the `hpShadow` mismatch
  makes `syncCenter()` re-derive them later, so the live view is fine). `parseKeyframes`
  (`src/animation.cpp:41-53`) copies `view` right after each load, so a shallow keyframe parsed
  after a deep one carries the deep keyframe's exact center. `applyPathTime`
  (`src/animation.cpp:116-123`) then interpolates `hp::lerp(B.hpRe, C.hpRe)` between two copies
  of the *same* string and overwrites the correctly splined `cs.cx/cy`.
- Confirmed with a two-keyframe path, k1 = `centerHP 0 1, height 1e-20`, k2 = `center -0.6 0,
  height 3`, exported at 2 fps for 1 s. The last frame (t = 1.0) matches a direct render centered
  at `0 + 1i` (`imgdiff` mean 2.3, 0.13 % bad) and not the expected view at `-0.6` (mean 7.3,
  2.5 % bad). The whole zoom-out stays pinned to the deep point.
- **Fix:** in `loadParText`, clear `hpRe/hpIm` when `classic.centerHP` is absent (or call
  `syncCenter()` at the end); `parseKeyframes` should also `syncCenter()` before copying. Add
  the regression test from §4.3.

### 1.3 [P2] "Fractint bands" has no effect on custom formulas: smooth coloring is a no-op
- `shaders/classic2d.comp:257` calls `escaped(z, i, 2.0, max(|z|, 1.0001))`, i.e. the bailout
  passed is |z| itself, so in `escaped` (`:100`) `lr / log(bail) = 1`, `nu = 0`, and the "smooth"
  value is the integer `i + 1`. With density 1 that lands on the same palette entry as the banded
  `i + 0.5`, and at other densities it is still a step function.
- Confirmed: Spider rendered with `classic.banded = 0` and `= 1` → `imgdiff` mean 0.000, max 0.
  The same pair for the built-in Mandelbrot differs (mean 0.49, max 7), as expected at density 1.
- **Fix:** user formulas don't declare a bailout radius or degree, but the common case is a
  degree-2 map escaping past 2. Compute `nu` from the standard log-log formula whenever |z| is
  above the biggest magnitude the loop test could have let through (or simply when |z| > 2), and
  let a formula override with a `; @power = 3` / `; @smooth = 0` annotation next to `@view`.
  Also the landscape's custom-formula branch (`fractals/landscape.glsl`, `log2(...)` clamp) can
  share the result. Until then the UI should say the toggle doesn't apply.

### 1.4 [P3] Deep zoom vs. fp64 agreement is looser than "isolated single-pixel noise"
- Measured on the test images (`build/test-out/deep-*.png`, 240×135, seahorse valley at
  5e-10, 8000 iterations): mean 3.6, **4.3 % of pixels off by more than 48**, and 12.3 % off by
  more than 8. At 960×540 it is the same fraction (4.2 %), so it is not a resolution artifact of
  the small test. The test passes only because `CMakeLists.txt:160` allows 8 %.
- The chaotic filaments amplify any per-iteration error, so some of this is inherent, but two
  design choices make it larger than it needs to be:
  - the reference orbit is stored as **fp32** (`src/deepzoom.cpp:117-123`,
    `src/renderer.cpp:375`), so every pixel's `2·Z·δ` term carries Z's rounding (~6e-8 relative)
    on every iteration; a `dvec2` SSBO costs 2× memory (32 MB → 64 MB at 4M iterations) and
    removes it;
  - the rebasing test `dot(zf,zf) < dot(d,d)` is the strict Zhuoran criterion, fine, but after a
    rebase δ is O(|z|) and carries only float precision until it shrinks again.
- **Suggested:** try the double reference first (one afternoon), re-measure, then tighten the
  test to what the renderer actually achieves (probably < 1 %). Also add a second, non-chaotic
  comparison point (inside a bulb's basin) where the two must agree to imgdiff's default
  tolerance.

### 1.5 [P3] Path-tracer noise repeats every 64 pixels
- `shaders/common.glsl:125-131`: the Sobol index shuffle and Owen seeds depend only on the
  dimension, not the pixel; the only per-pixel decorrelation is the Cranley-Patterson shift from
  a 64×64 blue-noise tile. Pixels 64 apart therefore use the *identical* sample set.
- Confirmed: preset 07 at 512², 2 samples, high-pass filtered; noise autocorrelation at a
  horizontal shift of 64 px is **+0.18** vs ≤ 0.04 at shifts 61–66 and +0.12 at 128.
- Invisible once converged, but visible as a faint texture while refining and in low-sample
  video frames. **Fix:** fold a per-pixel hash into the shuffle seed after the first few samples
  (Heitz/Belcour-style "blue noise for the first N, decorrelated after"), or use a 128–256 tile
  for the shift. The `rngSeed` signature already receives the pixel.

## 2. Bugs from reading (not run)

### 2.1 [P2] Idle sleep doesn't know about the reference-orbit worker or the Julia inset
- `computeIdle` (`src/app.cpp:784-802`) considers `job2D.active` but not `refPending` nor
  `inset.job.active`. After a deep zoom step the frame loop goes idle while the MPFR thread works,
  wakes every 250 ms (`src/app.cpp:690`), and the render starts up to a quarter second after the
  reference is ready. With the mouse resting on the set, the Julia inset (4 ms budget per frame)
  advances at 4 fps.
- **Fix:** `refPending || inset.job.active` → not idle.

### 2.2 [P2] History fills with playback frames; playback disables parameter animation for good
- `recordHistory` (`src/app.cpp:384-401`) skips drags and active widgets but not
  `camPath.playing` / `video.active`, so a 30 s path adds ~50 entries and pushes the user's real
  history out of the 200-entry ring (and Undo after playback steps through the flight).
- `applyPathTime` sets `p.animate = false` for every parameter (`src/animation.cpp:161`) and
  nothing restores it when playback stops.
- **Fix:** don't record while playing/exporting (record once when playback stops); save and
  restore the `animate` flags around playback like `video.restorePar` does for the view.

### 2.3 [P2] Keyframe parsing recompiles the formula shader once per keyframe
- `parseKeyframes` loads every keyframe through `loadParText`; with a custom formula that calls
  `compileFormula()` → `Renderer::setCustomFormula` (`src/renderer.cpp:191-200`), which
  synchronously rebuilds the compute program and **erases the landscape programs**. A path with
  N formula keyframes costs N+1 synchronous compiles every time `parsed` is invalidated (every
  "set", reorder, delete), and the 3D landscape restarts from black.
- **Fix:** memoize in `compileFormula`: if `formulaSource` and `fn[]` equal the last compiled
  pair, return early. That alone fixes the whole chain (`applyPathTime` already compares).

### 2.4 [P3] `loadParText` starts 3D settings from defaults but not 2D ones
- `src/params_io.cpp:146-157` resets `view.rs`, params and the camera before applying keys; the
  comment promises "a hand-written PAR only needs the keys it wants to change". `view.cs`,
  `view.fn`, `view.gradient`, `view.cosine` and `formulaName/Source` keep the *current* values,
  so a hand-written 2D PAR inherits the previous view's center, zoom, iterations and coloring.
  Saved PARs are complete, so only hand-written files, the hostile tests and the presets are
  affected (e.g. `03-deep-zoom-fp64.par` inherits `coloring`/`insideMode` from whatever was
  shown before it on the tour).
- **Fix:** `view.cs = Classic2DSettings()` and reset the formula/palette editors' state before
  the key loop (and clear `hpRe`, see 1.2).

### 2.5 [P3] Two leaks in the poster snapshot (review 1.4)
- Formula parameters p1–p3 reach the shader from `formulaP_`, which `frame()` refreshes from the
  live view every frame (`src/app.cpp:747`, used at `src/renderer.cpp:344`), not from
  `poster.cs`. Dragging p1 during a landscape-with-formula render mixes scenes.
- The custom formula's GLSL isn't snapshotted: recompiling mid-render erases and rebuilds the
  landscape program with the new formula (§2.3).
- **Fix:** pass the parameters through `renderSample3D`'s arguments (they are per-view state,
  not renderer state), and refuse or restart the poster when the formula changes.

### 2.6 [P3] Video finish/cancel can freeze the UI for a long time
- `finishVideo` (`src/animation.cpp:288-302`) calls `waitpid` synchronously. With `libx264
  -preset slow` at 4K the encoder flushes for seconds to minutes; `cancelVideo` closes the pipe
  and then waits for the *full* encode of what was written instead of `kill(pid, SIGTERM)`.
- **Fix:** on cancel, terminate ffmpeg; on finish, poll `waitpid(WNOHANG)` from `frame()` and
  toast when it exits.

### 2.7 [P3] Right-click / Space "Julia" with a custom formula loses the view and does nothing
- `toggleJulia` (`src/app.cpp:1014-1048`) guards Newton but not `kCustomFormula`. It sets
  `cs.julia = 1` and jumps to center 0 / height 3.2, but the CUSTOM_FORMULA path in the shader
  ignores `uJulia` (`frm_init(pixel)` always), so the user just sees their zoom vanish (the panel
  already hides the checkbox for formulas).
- **Fix:** same toast as Newton, or implement it properly by passing `uJuliaC` into `frm_init`
  as `p1` when the formula reads `p1` (which is how Fractint's Julia formulas work).

### 2.8 [P3] Two `glFinish` per compute pass serialize CPU and GPU every frame
- `stepJob2D` (`src/app.cpp:1236`, `:1251`) drains the whole pipeline to time each pass, and
  the Julia inset does it again. That makes the 12 ms budget measurable but also stalls the UI
  and display work behind it; with the inset on, a frame can contain three full stalls.
- **Fix:** measure passes with the existing `GpuTimer` (a query per pass, consumed one frame
  late to adapt `chunk`) and cap work per frame by the *previous* frame's measurement; or at
  least a fence + `glClientWaitSync` with a timeout instead of `glFinish`. Also `frameBudgetMs`
  is a fixed 12 ms (`src/app.h:229`) while the 3D path derives its budget from Target fps.

### 2.9 [P3] Nothing says "compiling shaders"
- Switching fractal before the warm-up finishes (or after editing a `.glsl`) shows black and
  "0/48 samples" until the async build lands; `Renderer::status()` knows it is `Compiling` but
  neither the HUD nor a toast says so (`grep Compiling src/ui.cpp` → nothing).

### 2.10 [P3] Null dereference on a live-edited `landscape.glsl`
- `flattenTo2D` (`src/app.cpp:1627-1636`) does `f.find("center")->value[0]` etc. without null
  checks; renaming a parameter while the app runs crashes the button. Same pattern in
  `liftTo3D` is guarded. Minor, but the whole point of hot reload is editing these files.

### 2.11 [P3] The GL RAII wrappers are copyable
- `Program` deletes its copy operations; `RenderTarget`, `IndexTarget` and `StateImages`
  (`src/gl_util.h`) don't, so a stray copy of `Poster` or `JuliaInset` would double-delete GL
  names. Nothing copies them today; make it impossible.

### 2.12 [P3] Function-local statics are back
- `src/ui.cpp:744-745` (`editRe/editIm/lastRe/lastIm` in the Exact-center tree) reintroduce the
  pattern that review 2.3 removed. Move them into `UiState`.

### 2.13 [P3] Path interpolation details
- Sun azimuth is splined without unwrapping (`splineFields`, `src/animation.cpp:73`): 350° → 10°
  turns 340° the long way; the camera yaw already unwraps (`:128`).
- Integer settings (`maxIter`, `bounces`, `supersample`, `power`) jump at keyframe boundaries
  (documented, but a 1000 → 8000 `maxIter` step mid-zoom is a visible pop in a video).
  Interpolate ints, `maxIter` in log space, and round.
- Catmull-Rom with uniform parameterization gives speed proportional to keyframe spacing; a
  per-segment ease-in/out toggle would remove the kinks at keyframes.

### 2.14 [P3] Small ones
- `undo()` (`src/app.cpp:419-432`) on an unrecorded change discards that change without pushing
  it, so it can't be redone. Record first, then step back.
- `computeIdle` never sleeps while any gamepad is connected (`src/app.cpp:789-790`); a
  plugged-in controller means vsync-rate polling forever. Use a short wait (50 ms) instead of
  none.
- HUD cursor coordinates (`src/ui.cpp:1348`) and the "Center real/imag" `InputDouble`s print
  doubles, meaningless past 1e13×; format from `hpRe/hpIm` in deep mode.
- The zoom ceiling is the double `cs.height` (`kMinHeight = 1e-290`); everything else is
  arbitrary precision. Worth a sentence in the Learn panel; storing log2(height) would lift it.
- Video sizes are forced even (`src/ui.cpp:961`) but `--size` on the command line isn't, so
  `--render x.mp4 --size 641x361` fails inside ffmpeg (yuv420p).
- `startVideo` leaves `SIGPIPE` ignored process-wide after the first export (harmless here).
- Two `#include <algorithm>` in `app.cpp` and `params_io.cpp`.

## 3. Rendering notes

- **Sampler math checked**: the Laine-Karras constants and the reverse-permute-reverse nesting
  match Burley 2020; index shuffling via nested scramble preserves the prefix property; dimension
  1 uses the all-ones direction matrix. Correct. Only the pixel decorrelation is weak (§1.5).
- **Perturbation shader checked**: the 2^e bookkeeping (`δ²` scaled by 2^e, `δc` by 2^(dE−e)),
  the Julia/Mandelbrot initial conditions, and rebasing to Z₀ = 0 are all exact; rebasing to the
  start of the reference is always valid because Z₀ = 0 makes δ₁ = z₁ − Z₁ identically.
  `ldexp(cM, dE − e)` can overflow to `inf` if δ ever shrinks 2^128 below a pixel (catastrophic
  cancellation); astronomically rare and the result is one NaN-colored pixel. A `clamp(dE − e,
  -200, 120)` costs nothing.
- **Glossy path tracing**: NEE uses a normalized Phong lobe while the bounce direction uses
  `mix(reflect, cosine, rough²)`; the two don't match, so indirect glossy light is biased relative
  to direct. Acceptable for an art renderer; note it in the shader so nobody "fixes" one side.
  The diffuse/glossy NEE scaling convention is consistent (both effectively ×π), checked.
- Frame 0 is a pinhole sample at the pixel center, later frames use the lens; the union set is
  very slightly unbalanced at low counts. Not worth changing.
- Custom formulas can't be shown in the orbit overlay (`src/ui.cpp:1536`) because they exist
  only as GPU code. The parser already builds the expression tree as strings; an interpreter over
  the same grammar (complex<double>) would give the orbit viewer, and a CPU fallback for tests.
- `stbi_write_png` on an 8K RGBA image is single-threaded zlib at level 8 and takes many
  seconds; `stbi_write_png_compression_level = 3` or a fixed filter halves it with no visible
  size penalty for these images.

## 4. Tests and repository

### 4.1 [P2] Tighten `deep.matches-fp64` after §1.4
Currently 8 % of the image may be wrong by more than 48/255 and the test still passes; that
would not catch a regression in the rebasing logic. Measured today: 4.3 %.

### 4.2 [P2] Round-trip coverage
`roundtrip.*` uses two presets, neither of which exercises `color.gradient`, `color.cosine`,
`formula.source` + `formula.fn`, `param.*.anim` or `classic.centerHP` (the last is covered by
`--self-test` only as text, not as an image). Add `tests/roundtrip/*.par` with one file per
feature and glob them like `hostile/`. The gradient one would also cover the palette-index
bookkeeping in `openDroppedFile`.

### 4.3 [P2] A path test that would have caught §1.2
Add `--path-time T` (render the path at time T to the `--render` PNG; useful for users too).
Then: export nothing, just `imgdiff` the frame at `T = duration` against a direct render of the
last keyframe's PAR, and `T = 0` against the first. Cheap, deterministic, no ffmpeg decode.

### 4.4 [P3] `oversize_render_fails` accepts any failure
`WILL_FAIL` passes for a segfault too. Use `PASS_REGULAR_EXPRESSION "exceeds the GPU's texture
size limit"` (and drop `WILL_FAIL`) so it tests the intended path.

### 4.5 [P3] `formula.unit` needs no GPU: run it in CI
A GitHub Actions job (Ubuntu, `apt install libglfw3-dev libepoxy-dev libmpfr-dev ninja-build`)
that builds and runs `ctest -R formula.unit` would give the repo a green badge without a GPU
runner, and catch compile breakage on GCC/Clang versions the workstation doesn't have.

### 4.6 [P3] Vendored ImGui carries 174 example files, docs and `.github` (8.3 MB)
Keep `imgui/*.{h,cpp}`, `backends/imgui_impl_{glfw,opengl3}.*`, `misc/cpp/`, `LICENSE.txt`;
document the trim in `third_party/README.md` (which already says only two backends are used).

### 4.7 [P3] Test-side nits
- `golden.*` renders every preset at 8 samples; preset 17 (1e100, 50k iterations) is the slowest
  test and would get slower with §1.4's double reference — fine, just noting it is the one to
  watch.
- `deep.matches-fp64` shells out through `sh -c` with unquoted `$<TARGET_FILE>`; a build path
  with a space breaks it. Use a small `.cmake` script like the other two.

## 5. Enhancements that fit the brief

Ranked by nostalgia-per-hour again, now that the big ones exist.

1. **[ENH] Import real Fractint `.PAR` files.** The classic collections (`FRACTINT.PAR`,
   thousands of user PARs from the 1990s) use `type=mandel center-mag=x/y/mag params=…
   maxiter=… colors=…` (with the run-length-encoded `colors=` palette). Mapping `type` to the
   built-in formulas and `colors=` to a 256-entry palette is a few hundred lines and turns the
   app into a viewer for 30 years of shared views. This is the single most Fractint thing left.
2. **[ENH] Bivariate linear approximation (BLA) for deep zooms.** Preset 17 iterates 50,000
   times per pixel; BLA skips the linear stretches and is the standard next step after
   perturbation + rebasing (10–100× at extreme depths). The reference-orbit worker already has
   everything it needs to build the BLA table.
3. **[ENH] Formula language coverage.** `if/elseif/else/endif`, `p4/p5`, the missing functions
   (`asin acos atan asinh acosh atanh floor ceil trunc round zero one cosxx`), `maxit`,
   `whitesq`. Most real `.frm` files from the archives use at least one of these.
4. **[ENH] CPU interpreter for formulas** (§3): orbit viewer and Julia inset for custom formulas,
   and GPU-free unit tests of the transpiler's semantics.
5. **[ENH] `--path-time`** (§4.3) and a PNG-sequence export option next to MP4.
6. **[ENH] Per-segment easing** and integer interpolation for paths (§2.13).
7. **[ENH] Split-double center for the 3D landscape** (`center` hi/lo floats) so "Lift into 3D"
   stays sharp to ~1e-13 instead of ~1e-4; the toast currently apologizes for this.
8. **[ENH] A "compiling…" state in the HUD** (§2.9) and a spinner on the fractal combo.

## 7. Verified-correct items (no action; recorded so they aren't re-litigated)

- `rotAxis` and its Sierpinski use (see §0).
- Perturbation recurrence, exponent bookkeeping and rebasing (see §3).
- Owen-scrambled Sobol implementation constants and structure (see §3).
- PNG `iTXt` writer: chunk layout, CRC over type+data, placement before `IEND`; reader bounds
  checks and both `tEXt`/`iTXt` accepted.
- `RefOrbitWorker` threading: `ready_`/`cancel_` are atomics, `orbit_` is written before
  `ready_` and read only after; `stop()` joins before `req_` changes; no data race.
- `Program` move semantics and the explicit teardown order in `Renderer::shutdown` /
  `App::shutdown`; GL objects die before the context.
- PAR values are sanitized after every load path (file, PNG, history, session, keyframes);
  enum indices are clamped before any table lookup found in the UI.
- Fresnel, glossy NEE normalization, sun/halo not double-counted, Russian roulette unbiased.
- Formula transpiler emits only known constructs; user identifiers are prefixed (`v_`), numbers
  go through `strtod`, so PAR/`.frm` input cannot inject GLSL.
- History/session/keyframes as PAR text: complete snapshots, exact round trip
  (`--self-test`), history not polluted by color cycling or parameter animation.
- Everything in §6 of the first review still holds.
